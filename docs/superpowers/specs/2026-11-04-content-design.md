# Контент в админке — дизайн

Согласовано в чате 2026-11-04. Каталог (товары, бренды, категории), S3 и защита админки — не в этом шаге.

## Зачем

Сейчас тексты, контакты, проекты, FAQ и статьи лежат в `web/src/data/*.ts`: любая правка — через разработчика и выкладку. Наполнять сайт после запуска будет разработчик по просьбе заказчика, потом — обученные менеджеры. Нужна админка, из которой правка сразу видна на сайте.

## Что решили

**Приложение `apps/content`.**
- **Настройки сайта** — одна запись (django-solo): город, адрес, телефон, почта, часы работы (строки «дни — время» с порядком), Viber, Telegram, Instagram, ссылка на карту, юрлицо, УНП, обещание по времени ответа, id организации в Яндексе (отзывы), видео шоурума. Название, слоган и меню остаются в коде.
- **FAQ** — вопрос, ответ, порядок (перетаскиванием в списке админки), отметка «на главной».
- **Проекты** — slug, название, тип (квартира / дом / ЖК), место, фото с alt, порядок, «опубликован». Связь с товарами — списком slug до появления каталога.
- **Ещё фото проекта** (после проверки 2026-11-04): несколько фото → галерея на весь экран поверх списка; на главной — 6 проектов и 3 статьи (decisions.md № 100–101).
- **Статьи блога** — slug, заголовок, дата, обложка с alt, лид, текст, «опубликована». Время чтения считается по тексту.
- **Галерея шоурума** — фото с alt и порядком.

**Текст статьи** — встроенный редактор Unfold (Trix): заголовки, жирный, курсив, ссылки, списки, цитата. Хранится HTML, при сохранении чистится `nh3` по белому списку тегов; `h1` превращается в `h2` (h1 на странице — заголовок статьи). Фронт выводит его в своих стилях. Картинки внутри текста — не в этом шаге.

**Акции** — пока отдельного типа нет (заказчик не описал, что это). Раздел меню «Блог и акции» остаётся. *Решение исполнителя.*

**API** — только чтение, без авторизации: `/api/site/`, `/api/faq/`, `/api/projects/`, `/api/posts/`, `/api/posts/<slug>/`, `/api/showroom/`. Картинки — в форме `ImageAsset` фронта (`src`, `width`, `height`, `alt`), `src` абсолютный.

**Обновление сайта после правки** — сохранение или удаление записи → Celery шлёт фронту `POST /api/revalidate` с тегом раздела и секретом → `revalidateTag(tag, "max")`. Адрес и секрет — в env; не заданы — ничего не шлём.

**Фронт** читает API в серверных компонентах через `"use cache"` + `cacheTag`. Не задан `NEXT_PUBLIC_API_URL` — берёт текущие демо-данные из `src/data` (демо на Vercel не ломается). Клиентские компоненты (шапка, форма, карточка товара) получают настройки через контекст из layout.

**Демо-записи** — команда `loaddemo`: заливает в базу то, что сейчас на фронте, вместе с картинками из `web/public/images` (в dev-compose папка смонтирована только для чтения). Повторный запуск обновляет записи по slug, а не дублирует.

## Не делаем сейчас

S3 и imgproxy (картинки пока в `/src/media`), картинки внутри статьи, акции, тексты услуг / доставки / оплаты / шагов / квиза (черновики — в коде до утверждения), бренды и категории.
