# Каталог: серии, варианты, цвета

Дизайн по обсуждению 11.11.2026. Решения, отмеченные «моё решение», принял исполнитель — их можно оспорить.

## Зачем

АртТепло продаёт через шоурум и менеджеров: на сайте нет корзины, любой путь заканчивается заявкой. Каталог должен:

- показать разнообразие форм и цветов, чтобы человек захотел приехать или оставить заявку;
- помочь выбрать конкретный вариант без 330 строк сразу: у одной высоты серии КЗТО или Guardo бывает от 100 до 1000 вариантов (секции × трубность × подключение × крепление × цвет);
- отправить менеджеру заявку с точным вариантом: серия, артикул завода, цвет, подключение.

Образец — home-heat.ru (разбор устройства — ниже). Делаем проще: одна страница на серию вместо страницы на каждую высоту или вариант.

## Цели

1. Список каталога показывает каждую серию в 2–3 формфакторах (низкий, средний, вертикальный), чтобы при листании было видно разнообразие.
2. Выбор бренда показывает сначала его модельный ряд плитками с фото, потом карточки только его серий.
3. На странице серии таблица вариантов за 1–2 клика (как подведены трубы, высота) сужается до десятка-двух строк.
4. Цвет виден ярко: образцы-кружки с надбавкой, отдельный образец «Любой RAL».
5. Менеджеры сами правят серии, фото, группы цветов и проценты в админке; прайс обновляется импортом и не затирает их правки.

## Не делаем

- Корзину, оплату, наличие и сроки в карточках (решение 57).
- Страницы брендов (решение 85 — отложено). Бренд — фильтр каталога с модельным рядом.
- Страницы-подборки («вертикальные радиаторы», «чёрные радиаторы») — позже, для поиска; в базе это будет фильтр с заголовком, не сущность.
- Отдельную страницу на вариант.
- Свой внутренний код товара, синхронизацию с 1С: показываем артикул завода.
- Royal Thermo, Carisa, комплектующие КЗТО, техническую арматуру SR (решение 122).
- **Вторая очередь, «на подумать»:** Радимакс (чугун: цена по числу секций, покраска и патина — часто суммой за секцию) и SR (вентили: отделки вместо размеров). Данных по ним нет, только их открытые сайты. Модель первой очереди не должна мешать добавить потом надбавку суммой, но сейчас её не делаем. «Vier» не берём.

## Чего нельзя допустить

- Таблицу, которая открывается сразу на сотнях строк.
- Десятки тысяч почти одинаковых страниц в поиске.
- Цены, которых нет в прайсе завода или у заказчика (CLAUDE.md). Неизвестное — «по запросу».
- Тексты с kztoradiator.by (бриф). Тексты и фото home-heat брать можно (решение 121).

## Ограничения

- Бэк: Django 6, DRF, Unfold, Postgres, Celery. Модели каталога (`Category`, `Brand`, `LeadTime`) уже в `backend/src/apps/catalog`, тег кэша `Tag.CATALOG`, сброс кэша фронта сигналом.
- Фронт: Next.js 16, Cache Components; `data/api.ts` с `"use cache"` и тегами. Без `API_URL` фронт работает на демо-данных из `web/src/data` — демо нужно перевести на новую форму данных.
- Фильтры каталога — в адресе (решение 20). Объём (≈60 тыс. вариантов на старте) не даёт фильтровать на клиенте: фильтрует и считает бэк.
- Цены на сайте — в BYN. КЗТО — BYN с НДС (kztoradiator.by). Guardo — ₽, € (Pilon), USD (полотенцесушители); Nova — ₽. Перевод — в разделе «Цены и курс».

## Как устроен home-heat (для справки)

1С-Битрикс: раздел → товар = серия в одной высоте (53 тыс.) → торговое предложение = вариант (1,28 млн). Половина разделов — подборки без своих товаров; товар привязан к нескольким разделам. У радиаторов страница — серия в одной высоте с ценой «от» и таблицей вариантов; у конвекторов и полотенцесушителей — страница одного варианта с той же таблицей. Над таблицей — чипы исполнений («2-трубный, боковое», «нижнее правое», «Хром», «RAL на выбор»), фильтры и колонки зависят от категории. У каждого товара свой код 1С. Фильтры по категориям:

| Категория | Фильтры |
| --- | --- |
| Трубчатые радиаторы | цена, высота, ширина, глубина, межосевое, мощность, площадь, секции, трубность, подключение, цвет, модель |
| Чугунные | то же + рабочее давление; подключение боковое или диагональное |
| Полотенцесушители | + тип нагрева (вода, ТЭН, кабель), форма, полочка |
| Внутрипольные конвекторы | без высоты и секций; длина, ширина, глубина, мощность, вентилятор, питание 24/220 В, тип, материал и шаг решётки |
| Арматура | цена, цвет, бренд |

## Модель данных

```
Category ─┐
Brand ────┼─< Series ─< Variant
          │     ├─< ColorGroup >─< Color
          │     ├─< SeriesImage
          │     ├─< SeriesFile
          │     └─< Showcase ── (Variant)
```

**Series — серия.** «Гармония А40», «Retta 6P», «Бриз В». Бренд, категория, название, адрес (slug), описание (HTML из редактора, чистится как у статей), материал, нагрев, рабочее давление, гарантия (по умолчанию из бренда), видео (ссылка), опубликована, порядок.

**Variant — строка таблицы вариантов.** Серия, артикул завода (уникален внутри бренда), активен.
- Общие числа — обычными колонками с индексами: высота, ширина, глубина, длина (у конвекторов), межосевое, секции, мощность (Вт), базовая цена BYN (в базовом цвете), вес, объём.
- Исполнение — полями: трубность (1–6), подключение (список ниже), встроенный термоклапан, положение (горизонтальное / вертикальное), крепление (стена / ножки).
- Особенное для категории — `attrs` (JSONField, GIN-индекс): у конвектора вентилятор, питание, тип/материал/шаг решётки; у полотенцесушителя тип нагрева, форма, полочка.
- Площадь обогрева не храним: считается из мощности (100 Вт на м², бриф).

**Подключение — фиксированный список:** боковое; диагональное; нижнее левое; нижнее правое; нижнее универсальное (левое или правое); нижнее по краям (седловое); нижнее центральное; под электрику слева / справа. Чипы исполнений собираются из сочетаний «трубность × подключение» у вариантов серии, отдельно не хранятся.

**Color — общая палитра.** Код RAL (или название завода, например «Кофейный муар»), название, hex, мат или глянец.

**ColorGroup — группа цветов серии с надбавкой.** Серия, название («Стандартные», «Технолак», «Любой RAL»), процент надбавки, цвета (M2M), признак «любой RAL» (без списка цветов, образец-радуга, цена **«по запросу»**: соседние цвета палитры у заводов стоят очень по-разному), порядок. Ровно одна группа серии — базовая (0 %), в её цвете хранится цена варианта. Цена в цвете = базовая цена × (1 + процент/100), округление до целых BYN (моё решение). Процент правят менеджеры в карточке серии — пересчитывается вся серия. Решено: точные цены цветов из прайсов не храним; у Guardo это даёт расхождение с прайсом до 1–4 % (технолак Pilon +16…20 %, «Цвет RAL» Retta/Torre +13,8…15 %).

**SeriesImage — фото серии.** Файл, alt, порядок; необязательно — цвет и положение, чтобы при выборе цвета или вертикального исполнения показать подходящее фото.

**SeriesFile — документы.** Название, файл (PDF): каталог, паспорт, сертификат.

**Showcase — формфактор в списке.** Серия, подпись («300 мм», «1800 мм, вертикальный»), вариант, по которому берутся высота и цена «от» (или высота, если вариант не важен — на усмотрение исполнителя), фото, порядок. 1–3 на серию. Нет ни одного — серия показывается одной карточкой с минимальной ценой.

**Без django-polymorphic.** Подтипы (радиатор, конвектор, сушитель) отличаются несколькими полями; общие списки, фильтры и подсчёты по одной таблице `Variant` проще и быстрее, чем join таблиц-наследников. Особенные поля — в `attrs`.

**Схема категории — в коде, не в админке.** Для каждой категории: какие фильтры (поле, подпись, вид: диапазон / список / цвета), какие колонки в таблице вариантов, по каким полям чипы. Категории меняются редко.

## Страницы

**Список `/catalog/[category]`.**
- Сверху выбор бренда. Выбран бренд — под ним полоса модельного ряда: плитки серий с фото; клик по плитке ведёт на страницу серии.
- Ниже сетка карточек-формфакторов (Showcase): фото, «Гармония А40 · 1800 мм, вертикальный», бренд, цена «от», кружки доступных цветов.
- Слева фильтры по схеме категории со счётчиками. Серия попадает в список, если подходит хотя бы один её вариант; формфактор — если подходит вариант его высоты (моё решение: так фильтр высоты прячет «чужие» формфакторы).
- Фильтры и бренд — в адресе (`?brand=kzto&height_min=…`). Подпись про цены «от» — под заголовком (решение 109).

**Серия `/catalog/[category]/[series]`.** Одна страница на всю серию; выбранный вариант, цвет и высота — в параметрах (`?v=<артикул>&color=<код>&h=1284`), каноническая ссылка — без параметров.
1. **Верх:** галерея, бренд и страна, название; пока вариант не выбран — характеристики диапазонами «от–до» и цена «от»; ряд цветов кружками с надбавкой; кнопка заявки. Выбран вариант — те же места показывают его точные цифры и цену в выбранном цвете.
2. **Варианты:**
   - вопрос «Как подведены трубы у вас сейчас?» — чипы со схемками (сбоку, снизу у края, снизу по краям, снизу по центру, по диагонали); только способы, что есть у серии;
   - чипы исполнений (трубность × подключение); по умолчанию выбрано самое частое, а не «Все»;
   - фильтры по схеме категории; высота, если пришли с формфактора, уже выбрана;
   - таблица: артикул, размеры, мощность, площадь, подключение, цвет (кружок + название), цена в выбранном цвете; 20 строк и «Показать все»; клик по строке выбирает вариант (верх страницы обновляется, адрес тоже).
3. **Чертёж «Размеры и данные»** выбранного варианта: контур с размерами, патрубки красным в местах подключения, межосевое подписано. Рисуется кодом из чисел варианта.
4. **О серии:** описание, расшифровка подключений и кодов завода.
5. **Файлы, «В проектах», похожие серии.**

**Заявка** — та же форма (бриф). В контекст уходят серия, артикул, размеры, подключение, цвет и цена; для «Любой RAL» — «RAL на выбор, цена по запросу». Ссылка в Telegram ведёт на страницу серии с параметрами варианта (решение 91).

## Импорт

- Команда на каждый источник: Guardo и Nova — xlsx (колонки: название, активность, размеры, цвет, межосевое, мощность, тип нагрева, модель, бренд, артикул, цена), КЗТО — см. открытые вопросы.
- Ключ — бренд + артикул. Повторный импорт обновляет числа и цены, новые варианты добавляет, пропавшие делает неактивными; описание, фото, группы цветов и проценты не трогает.
- Цвет у Guardo зашит в артикул (`R9016(M)`): импорт сводит такие строки в один вариант в базовом цвете, а цвета раскладывает по группам серии.
- Исполнение берётся из артикула и названия (xlsx лежит у заказчицы: «Guardo_и_Nova_Выгрузка_29_10_26_—_30_10_26_1.xlsx»; расшифровку кодов сверить с PDF-каталогами Guardo при написании импорта):
  - Pilon `2T-1200 4 BK 3/4"`: `2T` — трубность, `1200` — высота, `4` — секции, `BK` — боковое, `NK` — нижнее, `NKVN` — нижнее с вентилем снизу; цвет — в названии и в разделе (белый, технолак, чёрный);
  - Retta / Torre `6SP-1500-04 NK-GOR-R-FL R9016(M)`: модель, высота, секции; `BK` / `NK` — боковое / нижнее, `GOR` / `VER` — положение, `L` / `R` — сторона, `FL` — на ножках, `E-L` / `E-R` — под электрику; `R9016(M)` — цвет и мат/глянец, `RXXXX` — любой RAL;
  - Nova `NS-T3 1500 11 BV R9010(M)`: `T2` / `T3` — трубность, высота, секции, `S` — боковое, `B` — нижнее, `BV` — нижнее с вентилем;
  - название дублирует трубность и подключение словами («двухтрубный … боковое подключение»).
- Первый импорт сам создаёт группы цветов серии: цвета с одинаковой ценой — в базовую группу, остальные — по отношению к базовой цене (медиана, округлённая до целого процента). Повторный импорт кладёт новый цвет в существующую группу с тем же процентом (±1 п.), иначе — в новую группу «Новые цвета», которую видно в админке. Проценты существующих групп не меняет (моё решение).
- Не каждый цвет есть у каждого варианта (у Pilon технолак — у 15,5 тыс. из 17,8 тыс. вариантов). Поэтому у варианта есть список доступных групп цветов (M2M, по умолчанию все); его заполняет импорт, таблица и заявка показывают только доступные сочетания (моё решение).

**Демо без бэка** (CI собирает образ фронта без бэка, решение 118) — несколько серий на новой форме данных; фильтры и таблица в демо работают на клиенте по этим данным, счётчики можно не показывать (моё решение).
- Сброс кэша фронта — один раз в конце импорта, не на каждую строку.

## Цены и курс

- У варианта — цена в валюте прайса и сама валюта (BYN, RUB, EUR, USD); из неё считается и хранится цена в BYN, по которой фильтры и сортировка.
- Цена в BYN = цена × официальный курс Нацбанка РБ ÷ масштаб × (1 + наценка/100). Для BYN-прайса (КЗТО) курс и наценка не применяются, если не задана своя наценка.
- Курс — открытый API Нацбанка: `https://api.nbrb.by/exrates/rates/RUB?parammode=2` (так же EUR, USD), ответ — `Cur_OfficialRate` и `Cur_Scale` (у RUB масштаб 100). Ключ не нужен.
- Задача Celery beat раз в сутки ночью (beat уже есть, `django_celery_beat`): берёт курсы, сохраняет в таблицу курсов с датой, пересчитывает цены в BYN у вариантов в этой валюте одним запросом, сбрасывает кэш каталога один раз. API недоступен — остаётся вчерашний курс, ошибка в лог; ручной пересчёт — кнопкой или командой.
- Наценка — процент в админке. На старте — у бренда; позже добавим поле, к какой группе товаров (категория, серия) она относится. Модель цены не должна мешать этому расширению.
- Надбавка за цвет (группа цветов) применяется поверх цены в BYN.

## Первая очередь данных

- КЗТО — выгрузка из админки kztoradiator.by (сайт заказчицы), если не получится — разбор страниц сайта.
- Guardo, Nova — xlsx.
- Фото — пока руками: несколько серий, чтобы заполнить админку и смотреть локально. Скрипт раскладки фото по сериям, цветам и положению — когда появится S3 (на сервере мало места).
