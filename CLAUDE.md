# АртТепло — сайт шоурума радиаторов

art-teplo.by: каталог для заявок шоурума в Минске. Корзины, оплаты и личного кабинета нет — любой путь заканчивается заявкой, менеджер перезванивает.

Фронт (`web/`, Next.js 16) и бэк (`backend/`, Django + DRF + Unfold + Celery) работают на сервере ActiveCloud в Docker за nginx — пока по IP, без HTTPS, домен ещё смотрит на старый WordPress. Бэк держит заявки, контент сайта и каталог: серии, варианты и цены заводит импорт прайса. Наполненная база — пока только локальная. Что готово и что нет — `docs/todo.md`.

Правила для фронта и бэка — в `web/CLAUDE.md` и `backend/CLAUDE.md`: подгружаются, когда работаешь в этой папке.

## Источники правды

- `docs/brief.md` — структура, тексты, цифры и условия. Читать перед правкой контента или структуры.
- `docs/todo.md` — что готово и что осталось до запуска. Сделал пункт — отметь там.
- `docs/decisions.md` — журнал решений с причинами. Перед тем как менять поведение или вид, проверь, нет ли решения против. Новое решение — строка туда, а если меняется суть — и в brief.
- `DESIGN.md` — дизайн-система. Поменял токен в `web/src/styles/tokens.css` — поправь и здесь.
- `docs/stack.md`, раздел 7 — как устроены бэк, CI и деплой сейчас, чек-лист переезда на прод.
- `materials/` — исходники заказчика, только читать. `old-version/` — старый WordPress: его тексты — мусор из шаблона, не брать.

## Проверки перед «готово»

- Фронт, из `web/`: `npm run lint && npm run build`. Вёрстку смотреть на 375, 768 и 1440 px: текст не вылезает за рамки и не наезжает на соседние блоки.
- Бэк, из `backend/`: `uv run ruff check && uv run ruff format --check && uv run pytest` (pytest ждёт postgres из dev-compose, см. `backend/README.md`).

## Тексты сайта

- По-русски, на «вы», спокойно, без давления.
- Цифры, сроки и условия — только из brief или от заказчика. Неизвестное — видимая заглушка «[Уточнить у заказчика: …]», не выдумка.

## Подводные камни

- Заменил файлы в `web/public/images` — подними `IMAGES_VERSION` в `web/src/lib/asset.ts`, иначе браузеры до 4 часов показывают старые картинки.
- Демо закрыто от поисковиков (`robots` в `web/src/app/layout.tsx` и `web/src/app/robots.ts`): фото пока чужие. Снимать только при запуске на своих фото.
- Корневой `.gitignore` — из шаблона Python, его правила (`/lib/`, `/build/` …) привязаны к корню. Без `/` они прячут `web/src/lib`, и сборка на Vercel падает.
- Секреты — только в `.env` (на сервере и локально), в git их нет. Содержимое `.env` не выводить.

## Git

- `main` — то, что видит заказчик: из неё Vercel собирает сайт, а CI публикует образ бэка в GHCR. Попадает туда только через PR `develop → main` (релиз) или `hotfix/<тема> → main`. Напрямую в `main` не пушить и локально в неё не сливать: проверки и сборка образов идут на PR.
- `develop` — общая ветка. Работа — в `feature/<тема>` или `bugfix/<тема>` от `develop`, обратно — через PR. Hotfix после `main` влить и в `develop`.
- Сообщения — Conventional Commits, описание по-русски: `feat(catalog): фильтр по площади обогрева`, `fix(quiz): прогресс на первом вопросе`, `docs: …`, `style: …`, `refactor: …`, `chore: …`. Область — раздел сайта или папка.
- Коммитить, пушить и сливать — когда об этом просят. Релиз в `main` — только по явной просьбе.
