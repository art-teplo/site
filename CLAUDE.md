# АртТепло — сайт шоурума радиаторов

Новый art-teplo.by: каталог для заявок шоурума в Минске. Корзины, оплаты и личного кабинета нет — любой путь заканчивается заявкой, менеджер перезванивает. Сейчас это фронт-демо для заказчика на Vercel; бэкенд (Django + DRF) будет позже на своём сервере.

## Где что

- `web/` — фронт на Next.js 16. Правила кода и структура — `web/README.md` (подключён ниже).
- `docs/brief.md` — что строим: единый источник правды по структуре, текстам, цифрам и условиям. Читать перед любой правкой контента или структуры.
- `docs/decisions.md` — журнал решений с причинами. Перед тем как менять поведение или вид, проверь, нет ли там решения против.
- `docs/images-manifest.md`, `docs/demo-photos.md` — слоты фото и откуда взяты демо-снимки; `docs/stack.md` — будущая инфраструктура.
- `materials/` — исходники (документы заказчика, референсы). Только читать: актуальное — в `docs/` и коде.
- `old-version/` — старый сайт на WordPress, в `.gitignore`. Его тексты — демо-мусор из шаблона, не брать.

## Команды (из `web/`)

```bash
npm run dev                  # http://localhost:3000
npm run lint && npm run build # перед тем как назвать работу готовой
npm start -- -p 3000 -H 0.0.0.0  # показать с телефона в локальной сети
```

Вёрстку проверять на 375, 768 и 1440 px: текст не вылезает за рамки и не наезжает на соседние блоки.

## Правила работы

- Тексты сайта — по-русски, на «вы», спокойно, без давления. Цифры, сроки и условия — только из `docs/brief.md` или от заказчика. Неизвестное — видимая заглушка «[Уточнить у заказчика: …]», не выдумка.
- Решение, которое меняет поведение, структуру или контент, — строка в `docs/decisions.md` (что и почему); если меняется суть — и в `docs/brief.md`.
- Заменили файлы в `web/public/images` — поднимите `IMAGES_VERSION` в `web/src/lib/asset.ts`, иначе браузеры до 4 часов показывают старые картинки.
- Демо закрыто от поисковиков (`robots` в `web/src/app/layout.tsx` и `web/src/app/robots.ts`): фото пока чужие. Снимать только при запуске на своих фото.
- Корневой `.gitignore` собран из шаблона Python: его правила (`/lib/`, `/build/` …) привязаны к корню. Без `/` они прячут `web/src/lib`, и сборка на Vercel падает.

## Git

Gitflow:
- `main` — то, что видит заказчик: Vercel выкладывает сайт из неё. Попадает туда только слиянием из `develop` (релиз) или `hotfix/*`.
- `develop` — общая ветка разработки.
- Работа — в `feature/<тема>` или `bugfix/<тема>` от `develop`, слияние обратно через `--no-ff`. Срочная правка живого сайта — `hotfix/<тема>` от `main`, потом слить в `main` и `develop`.

Сообщения — Conventional Commits, описание по-русски: `feat(catalog): фильтр по площади обогрева`, `fix(quiz): прогресс на первом вопросе`, `docs: …`, `style: …`, `refactor: …`, `chore: …`. Область — раздел сайта или папка.

Коммитить и пушить — когда об этом просят; в `main` — только по явной просьбе, это выкладка заказчику.
