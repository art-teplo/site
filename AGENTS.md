# АртТепло — сайт шоурума радиаторов

art-teplo.by: каталог для заявок шоурума в Минске. Корзины, оплаты и личного кабинета нет — любой путь заканчивается заявкой, менеджер перезванивает.

Фронт — `web/` (Next.js 16), бэк — `backend/` (Django + DRF + Unfold + Celery), инфраструктура — `root/` (Docker Compose, nginx, скрипты). Бэк держит заявки, контент сайта и каталог: серии, варианты и цены заводит импорт прайса. Что готово — `docs/todo.md`; последнее зафиксированное состояние сервера ActiveCloud — `docs/stack.md`, раздел 7. Запись о сервере с датой не заменяет текущую проверку.

Общие правила для агентов — этот файл. Перед работой в части проекта явно прочитай её `AGENTS.md`: `web/AGENTS.md`, `backend/AGENTS.md` или `root/AGENTS.md`. Перед правкой `.github/` также прочитай `root/AGENTS.md`. Не полагайся на автоматическую загрузку вложенных файлов при старте из корня. `CLAUDE.md` — только совместимый импорт этих же правил для Claude Code.

## Начало работы

- Проверь текущую ветку и `git status`; сохраняй чужие незакоммиченные изменения.
- На вопрос «почему/как» сначала ответь и предложи изменение. Явную просьбу «сделай/исправь/адаптируй» выполняй в её пределах.
- Старые чаты, экспорт и личная память — справочный контекст: сверяй их с кодом и документами. Старое разрешение на деплой или слияние не является разрешением для новой задачи.
- Пользуйся доступными в текущей сессии инструментами и навыками. Название плагина или инструмента в старом чате не подтверждает, что он подключён сейчас.

## Источники правды

- `docs/brief.md` — структура, тексты, цифры и условия. Читать перед правкой контента или структуры.
- `docs/todo.md` — что готово и что осталось до запуска. Сделал пункт — отметь там.
- `docs/decisions.md` — журнал решений с причинами. Перед тем как менять поведение или вид, проверь, нет ли решения против. Новое решение — строка туда, а если меняется суть — и в brief.
- `docs/admin-guide.md` — как поля админки влияют на каталог (фото, подписи, цены, цвета, видео). Поменял эту логику — поправь гайд.
- `DESIGN.md` — дизайн-система. Поменял токен в `web/src/styles/tokens.css` — поправь и здесь.
- `docs/stack.md`, раздел 7 — как устроены бэк, CI и деплой сейчас, чек-лист переезда на прод.
- `docs/ai-workflow.md` — как устроены инструкции Codex/Claude/ChatGPT, перенос контекста и выбор документов для обновления.
- `docs/superpowers/specs/` и `docs/superpowers/plans/` — спецификации и планы этапов. Проверяй их статус по текущему коду, `todo.md` и более поздним решениям; не запускай старый план заново только из-за его наличия.
- `materials/` — исходники заказчика, только читать. `old-version/` — старый WordPress: его тексты — мусор из шаблона, не брать.

## Проверки перед «готово»

- Фронт, из `web/`: `npm run lint && npm run build`. Вёрстку смотреть на 375, 768 и 1440 px: текст не вылезает за рамки и не наезжает на соседние блоки.
- Бэк, из `backend/`: `uv run ruff check && uv run ruff format --check && uv run pytest` (pytest ждёт postgres из dev-compose, см. `backend/README.md`).
- Инфраструктура — проверки из `root/AGENTS.md`.
- Для правок только Markdown проверь ссылки, пути, команды по исходникам и `git diff --check`; сборки приложения и проверка вёрстки не нужны. Для изменений кода выполняй проверки соответствующей части. В отчёте укажи, что запустил и что осталось непроверенным.

## Тексты сайта

- По-русски, на «вы», спокойно, без давления.
- Цифры, сроки и условия — только из brief или от заказчика. Неизвестное — видимая заглушка «[Уточнить у заказчика: …]», не выдумка.

## Подводные камни

- Заменил файлы в `web/public/images` — подними `IMAGES_VERSION` в `web/src/lib/asset.ts`, иначе браузеры до 4 часов показывают старые картинки.
- Демо закрыто от поисковиков (`robots` в `web/src/app/layout.tsx` и `web/src/app/robots.ts`): фото пока чужие. Снимать только при запуске на своих фото.
- Корневой `.gitignore` — из шаблона Python, его правила (`/lib/`, `/build/` …) привязаны к корню. Без `/` они прячут `web/src/lib`, и сборка на Vercel падает.
- Фото в коде (импорт, команды): `image_width`/`image_height` задавать после `obj.image.save(…, save=False)`, перед `obj.save()`. Запись файла перечитывает размеры из хранилища, в S3 они выходят пустыми — и тогда каждый запрос каталога скачивает файлы заново (так API тормозил до 16 с).
- Секреты — только в `.env` (на сервере и локально), в git их нет. Содержимое `.env` не выводить.
- На сервере руками — только `/opt/art-teplo/.env`. Скрипты, compose, nginx и cron (`root/`) приезжают с деплоем (`deploy.yml` → `deploy.sh`): правьте в репозитории, на сервер не копируйте.

## Git

- `main` — то, что видит заказчик: из неё Vercel собирает сайт, а CI публикует образ бэка в GHCR. Попадает туда только через PR `develop → main` (релиз) или `hotfix/<тема> → main`. Напрямую в `main` не пушить и локально в неё не сливать: проверки и сборка образов идут на PR.
- `develop` — общая ветка. Работа — в `feature/<тема>` или `bugfix/<тема>` от `develop`, обратно — через PR. Hotfix после `main` влить и в `develop`.
- Сообщения — Conventional Commits, описание по-русски: `feat(catalog): фильтр по площади обогрева`, `fix(quiz): прогресс на первом вопросе`, `docs: …`, `style: …`, `refactor: …`, `chore: …`. Область — раздел сайта или папка.
- Коммитить, пушить и сливать — когда об этом просят. Релиз в `main` — только по явной просьбе.
